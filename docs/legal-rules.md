# כללי ההצבעה בקלפי נגישה מיוחדת — מצב אימות

עודכן: 20.10.2026

## מצב: **ממתין לנוסח רשמי** (`status: pending-official-text`)

כל עוד הכלל לא אושר מול הנוסח הרשמי, האתר **אינו מציג קלפיות** ואינו מציג את נוסח התנאים, לפי אפיון §6.1 ו־§16. במקום זה מוצג מסלול בירור רשמי.

העמוד הרשמי S1 (`gov.il/he/pages/26elections-info?chapterIndex=7`) והעמוד `gov.il/he/pages/accessibility_26` **לא נקראו**: הגישה אליהם חסומה מסביבת הפיתוח. גם נוסח החוק העדכני לא נקרא ממאגר רשמי.

## הנוסח המוכן להצגה (config/rules.json)

הנוסח מצומצם בכוונה. הוא כולל ארבע נקודות בלבד: התנאי הבסיסי, מעטפה כפולה ותעודה מזהה, הצהרה אפשרית (בנוסח שהאפיון עצמו אישר), והבהרה שהאתר אינו קובע זכאות. האתר אינו מכריע ב"נכות נראית לעין" ואינו מפרט עבירות.

## איך מאשרים (צעד אנושי, חובה)

1. פתחו את העמוד הרשמי S1 ואת עמוד ההתאמות לאנשים עם מוגבלות באתר ועדת הבחירות.
2. העתיקו את הטקסט הרשמי הרלוונטי לקובץ `docs/legal/s1-official-excerpt.txt`.
3. השוו אותו לנקודות ב־`config/rules.json` (שדה `texts.he`). אם יש הבדל מהותי, תקנו את הנוסח בכל ארבע השפות והעלו את `version`.
4. הריצו:
   ```
   npm run rules:approve -- --excerpt docs/legal/s1-official-excerpt.txt --start "<המילים הראשונות של הקטע>" --end "<המילים האחרונות>" --reviewer "<שם הבודק>"
   ```
   הפקודה שומרת hash של הקטע הרשמי. מכאן ואילך הרענון היומי בודק שהקטע לא השתנה, ושינוי בו **חוסם** את ההצגה עד לבדיקה חוזרת.
5. העבירו את `state/state.json` המעודכן לענף `data-state` (או הריצו את ה־workflow), ובנו מחדש.
